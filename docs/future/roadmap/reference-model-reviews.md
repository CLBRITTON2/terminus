Develop reference-based reviews that surface consequential places for operator judgment: departures from house conventions and architectural differences whose quality needs consideration. Ground the integration in Console's first reference and authoring work, then decide how references participate alongside existing canon qualities.

## why

From Michael's presentation of mega, 2026-11-18, the fifth of seven future directions: "terminus grows support for reference model reviews. terminus supports a quality steering based on reference architecture components."

A quality today is prose: a statement, a reason, and what to flag and what to leave alone. That works for a rule that fits in a paragraph. It works less well for "build it the way that one is built", which is how a lot of good structure is actually passed on. The console project's own instructions already call it the standard for its kind.

Captured here by the planning agent on mega, where the hub epic, `mega-as-the-development-hub` in mega's roadmap, first listed this as "terminus referencing complete architectural examples".

## existing design work

A reference is a coherent working example; a pattern is an arrangement it demonstrates. The reference canon serves design conversations, implementation, and review, with Terminus as one consumer. A different arrangement can achieve comparable architectural quality; references help agents identify where operator judgment matters rather than replace it.

The [reference authoring guide](../../../../console/docs/future/reference-authoring.md) and [Console reference draft](../../../../console/docs/future/console-reference.md) are provisional artifacts from the November design conversation. Develop and exercise Console first, using it in a design conversation and a bounded review before committing to broker machinery. The [Console journal](../../../../console/docs/journal/2026-11-12.md) records the agreed vocabulary and the distinction between settled direction and proposed mechanisms.

## to design for

- **Selection and context.** Decide how a review selects relevant patterns and supplies enough surrounding context to understand their interactions. A quality naming a component and component-only loading are possible mechanisms, not settled requirements.
- **Versioning.** A reference version identifies code, explanations, patterns, and demonstrations together. A new version must not silently change an earlier design's basis. Tags backed by exact commits are proposed; numbering and where adoption is recorded remain open.
- **What a finding says.** "Differs from the reference" is not a finding. Which difference matters, and why, is.
- **Relationship to qualities.** Decide how references and prose qualities coexist, what authority each carries, and how reference-based observations affect findings and verdicts.
- **Where references live.** The first reference and guide are being developed in Console. Decide how the wider canon catalogs and locates versioned references without assuming their code must move into the canon repo.
